# Slice 01: Backend scaffold

## Goal
A runnable, tested backend foundation: the Phase 0 project structure and tooling, PostgreSQL in
Docker Compose, a FastAPI app with health checks, async database session management, the first
migration (workflow templates, runs and tasks), endpoints to create and read workflow templates,
and CI.

## What was built
- **Project:** `backend/` uv project (`pyproject.toml`, `uv.lock`, Python 3.12) with ruff, mypy (strict)
  and pytest configuration. Package layout per the roadmap: `api`, `core`, `models`, `schemas`, `services`,
  plus empty `orchestration`, `agents`, `tools`, `workers` and `events` packages for later phases.
- **Infrastructure:** `docker-compose.yml` (PostgreSQL 17, host port 5433, healthcheck, named volume),
  `.env.example`, `.github/workflows/ci.yml`.
- **Configuration and database:** `app/core/config.py` (pydantic-settings), `app/core/db.py` (engine and
  session factories), `app/main.py` (`create_app()` with a lifespan that owns the connection pool).
- **Schema:** `workflow_templates`, `workflow_runs`, `tasks` (`app/models/`, migration `0001_initial_schema`).
- **Endpoints:**

  | Method | Path | Result |
  |---|---|---|
  | GET | `/health` | 200 when the process is up |
  | GET | `/health/ready` | 200 when the database answers within 2 s, else 503 |
  | POST | `/api/workflows` | 201 created, 409 duplicate name, 422 invalid |
  | GET | `/api/workflows?limit&offset` | newest first; `limit` 1–100 (default 50) |
  | GET | `/api/workflows/{id}` | 200, 404 unknown, 422 malformed UUID |

  In the API, a "workflow" is a template; runs will live under `/api/runs`.

## How it works
**Request flow.** `POST /api/workflows` → Pydantic validates the body (`WorkflowTemplateCreate`) →
`get_session` opens an `AsyncSession` from the pool → `services.workflow_templates.create_template`
executes `INSERT ... ON CONFLICT (name) DO NOTHING RETURNING *` and commits → the route serializes the
committed row. A conflict returns no row; the service raises `TemplateNameConflictError`, mapped to 409.
Leaving the session context closes it and rolls back anything uncommitted.

**Data model.**

```text
workflow_templates 1 ──< workflow_runs 1 ──< tasks
  (definition JSONB)     (ON DELETE RESTRICT)  (ON DELETE CASCADE, unique (run_id, key))
```

A template's task graph is one JSONB document:

```json
{"tasks": [
  {"key": "gather_evidence", "name": "Gather evidence", "depends_on": []},
  {"key": "analyze_logs", "name": "Analyze logs", "depends_on": ["gather_evidence"]}
]}
```

Run tasks are individual rows because workers will lock and update them one at a time. Status columns
are `VARCHAR(32)` with CHECK constraints (`ck_workflow_runs_run_status`, `ck_tasks_task_status`).
Runs and tasks have tables and tests in this slice; their endpoints arrive with the orchestration engine.

**Migrations.** Alembic's async `env.py` reads the URL from settings (an explicitly configured URL, as set by
tests, takes precedence) and compares against `Base.metadata`. Migration `0001` was autogenerated, then
rewritten by hand to declare CHECK constraints explicitly with convention-based names.

## Why this approach
- Data model choices (UUID keys, VARCHAR + CHECK statuses, JSONB template definitions, normalized tasks,
  RESTRICT/CASCADE): [ADR-0003](../decisions/0003-initial-data-model.md).
- Session per request, services commit before the response, `expire_on_commit=False`, uniqueness enforced by
  the database: [ADR-0004](../decisions/0004-session-and-transaction-boundaries.md).
- Real PostgreSQL test database built by migrations, truncate between tests:
  [ADR-0005](../decisions/0005-test-database-strategy.md).
- The readiness check returns a generic message: connection errors can include hosts or credentials.
- Template definitions are capped at 100 tasks and reject unknown fields, limiting oversized or unexpected
  input at the API boundary.

## Tests
34 tests, all against PostgreSQL except the unit tests.
- **Unit** (`tests/unit/`): definition validation (valid DAG; empty, duplicate keys, unknown dependency,
  self-dependency, bad key format, more than 100 tasks, unknown fields); settings read from the environment.
- **API** (`tests/integration/test_workflow_templates_api.py`): create then read back through a separate
  session (proves the commit); duplicate → 409; **five concurrent creates with one name → exactly one 201**
  (proves there is no check-then-insert race); invalid payloads → 422; unknown ID → 404; malformed ID → 422;
  list order and pagination bounds.
- **Database guarantees** (`test_models.py`): server defaults applied; raw-SQL invalid status rejected by the
  CHECK constraint; duplicate `(run_id, key)` rejected; run delete cascades to tasks; template with runs cannot
  be deleted; a failed commit persists nothing from its unit of work.
- **Health** (`test_health.py`): liveness; readiness with the database up; readiness → 503 with an unreachable
  database, without leaking connection details.
- **Migrations** (`test_migrations.py`): downgrade to base and upgrade to head; `alembic check` reports no drift.

No failure-injection tests yet: this slice has no durability features (claiming, leases, retries).
